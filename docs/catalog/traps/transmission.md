# Transmission traps

## Pitfalls

- This private recipe does not publish the TCP/UDP peer port or establish a VPN kill switch. Incoming peers and VPN-safe downloading require separately approved work.

## Security

- Keep the authenticated RPC/WebUI bound to loopback; separately approve peer-port publication and downloader VPN routing.

## Arr download-client Link

- Sonarr/Radarr API v3 and Lidarr API v1 use the discovered `Transmission` / `TransmissionSettings` provider. The leaf declares the shared Torrent protocol family, not a value inferred from API prefix or version. Sonarr/Radarr retain exact `torrent`; supported Lidarr 3.x/v1 source families expose `torrent` (3.1.0.4875) or `TorrentDownloadProtocol` (3.1.6.5079). These are independently admitted literals, not interchangeable aliases. The unique authenticated schema and recorded resource must agree exactly before target credential reads, RPC/exec, native testing or private/resource writes. Creation/native/credential-update requests retain that actual literal; returned protocol mismatches cannot acquire an owned ID or advance a fingerprint. No ownership migration or canonical protocol is introduced.
- Common tuple/schema/authentication admission is centrally owned; this leaf adds no duplicate protocol allowlist, version cutoff or consumer/API selector. It uses the selected Compose service/container port and accepted Project Admin login, and retains category/directory/imported-category, priority, paused and cleanup choices. It never replaces qBittorrent or selects a preferred client. Unknown or crossed wire contracts stay Manual before target activity; successful literal admission alone does not establish the running image's native behavior.
- A dedicated nonempty category is required by the shared download-provider boundary. Transmission has per-torrent labels, not a category-creation API. No torrent is added, moved, relabeled or removed by verification. New managed connections receive the aggregate's tv/movies/music category; existing category choices are retained.
- The checked stable Sonarr 4.0.20.3014, Radarr 6.4.4.10685 and Lidarr 3.1.6.5079 append category subdirectories and reject category plus directory together. Newer Sonarr/Radarr source can use native labels without a subdirectory and can permit both fields. The Link does not infer one universal behavior: without an explicit directory it conservatively verifies both the daemon default and category subdirectory; with one it verifies that actual directory and leaves provider-specific category/directory validation to Arr's native test. Missing directories remain Manual, never created automatically. Both candidate folders being safe is a conservative prerequisite, not proof of which one a particular image will use.
- Target-owned verification reuses the existing accepted RPC/session/queue probe and reads only `download-dir`, `incomplete-dir-enabled` and, when enabled, `incomplete-dir`. Positive Basic credentials accompany every request; redirects and failed/missing session negotiation are rejected. Disabled/unverifiable saved authentication policy, unavailable credentials, unsupported RPC or malformed data stays Manual with a persisted recovery hint. No credential rotation, policy bypass or target Setup is invoked by the Link.
- Every possible completed destination and enabled incomplete folder must pass the shared App-user access/backing-storage and library-separation checks before Arr's authenticated native test. A disabled incomplete folder is ignored. LinuxServer's enabled `/downloads/incomplete` default is not automatically remapped when shared storage uses `/data/torrents`; review it explicitly without moving active downloads.
- In legacy layouts Transmission's App-local `/downloads`, Arr's `${DOWNLOADS_ROOT}` and Lidarr's App-local `/data` are not automatically the same backing storage. Existing correct Remote Path Mappings are preserved and matched to the actual selected host. Missing roots, inaccessible paths, mismatched mounts or overlapping libraries remain Manual; no mount/path-map/global-folder mutation or hardlink/import proof is implied.
- Retry `self-host setup transmission` to recover its accepted login/policy, then `self-host setup sonarr`, `radarr` or `lidarr`. Preserve existing files and settings; do not reinstall or disable authentication to retry. A directory-only choice without an isolated category is preserved but held Manual by the current shared boundary. Unknown creation outcomes, unowned collisions or edited connection credentials require an explicit ownership decision, not automatic adoption or replacement. Removal uses only the recorded consumer connection ID and does not need target authentication or touch torrent data.
- Aggregate constructor assembly and resolved-image/native/lifecycle acceptance are coordinator-owned. Leaf constructor tests and a test-only consumer wrapper exercise the production Setup/Link scheduler with truthful old/new Lidarr status/schema pairs, both installation orders, absent/unready targets and offline removal; no production constructor registration changes are included. Focused HTTP/command-fake evidence is not a real connection, rendered-widget, download, hardlink or import acceptance claim. The earlier latest-only source check is not cross-family or whole-ticket acceptance. Existing target Setup's global-folder policy is unchanged; the new Link is read-only toward Transmission.

## Homarr contract

- Transmission 4.1.3 (RPC 6.0.1) retains the legacy RPC protocol used by Homarr 2.4.1's `@ctrl/transmission` 7.4.0. Readiness and `session-get`, `session-stats`, and `torrent-get` send the Shared Admin Basic credentials. Each RPC read negotiates a fresh session ID and rejects missing fields, unsupported versions and authentication/session failures.
- Setup sends no anonymous challenge: Transmission counts missing authentication toward brute-force limits, including thresholds of one. The App owner returns only the saved `rpc-authentication-required` boolean through the image's existing `jq`; missing, disabled or ambiguous policy stays Manual. This saved flag does not prove current in-memory enforcement after an unapplied configuration edit. Restart applies policy; live enforcement remains a separate acceptance observation. Configuration and credential contents are never returned or logged.
- The Homarr descriptor reuses Transmission's own Project Admin login without generating, adopting or rotating credentials. It keeps `http://transmission:9091` separate from the browser Address, and does not change RPC authentication, IP/host whitelists, peer ports or download state. Existing access-policy failures need review and a Setup retry, not an automatic policy bypass.
- Downloads show up to 50 items. Shared Stats use only `download`, `upload` and `paused`: rates are bytes per second summed over all torrents, not session totals or a queue count. Homarr considers an empty queue paused. Explicit empty arrays, zero rates and boolean paused values are valid; absent data, body errors or failed/stale Stats are not.
- Registry assembly belongs to the reference owner. Native API, rendered widget and lifecycle proof remains pending the parent's disposable Project runtime batch; source checks and fake-backed tests are not that proof. No downloads or tracker traffic are part of Setup or Link verification.
