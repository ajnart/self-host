# Deluge traps

## Pitfalls

- Daemon, Web UI, peer ports, and plugin behavior must be planned separately.
- The image documents no first-start password environment variable, and post-start RPC rotation leaves a default-password window on a shared Compose network.

## Arr download-client Link

- Sonarr and Radarr use API v3 with protocol `torrent`. Lidarr API v1 has two source-backed wire families: 3.1.0.4875 emits enum-wire `torrent`, while 3.1.6.5079 emits the string `TorrentDownloadProtocol`. The unique authenticated live schema supplies the exact value; Setup preserves it without choosing a preferred spelling or guessing a version cutoff. Existing resources must match that schema byte-for-byte, including during removal; crossed representations require explicit review, not a protocol or ownership migration. See the [older torrent base](https://github.com/Lidarr/Lidarr/blob/350860e524029b7fb4165ed14fbcabb11217ada2/src/NzbDrone.Core/Download/TorrentClientBase.cs#L44), [older enum resource](https://github.com/Lidarr/Lidarr/blob/350860e524029b7fb4165ed14fbcabb11217ada2/src/Lidarr.Api.V1/DownloadClient/DownloadClientResource.cs#L9-L45), [camel-case enum serializer](https://github.com/Lidarr/Lidarr/blob/350860e524029b7fb4165ed14fbcabb11217ada2/src/NzbDrone.Common/Serializer/System.Text.Json/STJson.cs#L33), [newer torrent base](https://github.com/Lidarr/Lidarr/blob/77de65260250020be99e417b027752b1f1730c08/src/NzbDrone.Core/Download/TorrentClientBase.cs#L44) and [newer string resource](https://github.com/Lidarr/Lidarr/blob/77de65260250020be99e417b027752b1f1730c08/src/Lidarr.Api.V1/DownloadClient/DownloadClientResource.cs#L8-L44).
- Their provider is `Deluge` / `DelugeSettings`, using Deluge's Web JSON-RPC endpoint `/json` and the saved `DELUGE_WEB_PASSWORD`. This is not a daemon username/password connection on port 58846 and is independently verified from each Arr provider, not inferred from Homarr.
- The Link uses the internal Compose service and container Web port, independently of the published port or selected Access. It adds an additional owned download client without replacing qBittorrent, selecting profiles or starting torrents.
- Enable the built-in **Label** plugin explicitly in Deluge Preferences > Plugins, then create the chosen labels in Deluge before retrying the consumer's Setup. New labels are `tv`, `movies` and `music` for Sonarr, Radarr and Lidarr. Existing normal and post-import labels are preserved and must already exist. Arr's connection test can create missing labels, so missing plugin capabilities or any selected label is a Manual step before that test, provider creation or credential update. Setup does not enable/install plugins or create/delete labels.
- The Web session must already be connected to the intended local daemon. The Link verifies host-list identity and `web.get_host_status`, not only `web.connected`; an ambiguous, disconnected or different backend requires an explicit Connection Manager decision. It never changes the selected daemon, daemon accounts or remote-access settings.
- Download destinations come from the actual stored `downloadDirectory`, `completedDirectory`, normal/post-import Label move settings and daemon defaults. Active destinations and Arr's reported destination are checked against the consuming App's configured library roots through the shared read-only App-user path verifier. An unset library, inaccessible path or overlap remains Manual; paths, mappings, libraries, profiles and files are not migrated.
- Shared layout uses `/data/torrents` for Deluge and the consumer's common `/data` parent. Stock legacy layouts are not equivalent: Deluge's App-local `/downloads`, Sonarr/Radarr's `${DOWNLOADS_ROOT}` and Lidarr's App-local `/data` can hold different data. An existing Remote Path Mapping must match the selected provider host and lead to a verified common backing directory; rewriting a path string alone is not sufficient. Unsupported App-user or mount probes remain Manual, never a root fallback. These checks do not prove hardlinks or actual imports.
- Missing/rejected saved Web credentials require recovery through the Project's private credential boundary and `self-host setup deluge`, then `self-host setup sonarr`, `self-host setup radarr` or `self-host setup lidarr`. Do not rotate credentials or disable authentication to make a retry pass. Review edited or uncertain owned connections explicitly; matching names/hosts never establish ownership.
- Reruns retain recorded owned IDs and person-selected category/directory/priority choices. Removing Deluge deletes only each recorded Arr download-client resource; it does not require working target credentials, Label or path probes, and preserves manual clients, labels, mappings, torrents and target data.

## Security

- Keep the Web UI and daemon control port private and protect their authentication.
- The documented initial WebUI password is shared; change and verify it before granting access or joining untrusted services to its network.
- Do not advertise VPN-safe downloader egress without a recorded tunnel-break fail-closed test.
