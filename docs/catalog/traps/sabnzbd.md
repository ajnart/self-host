# SABnzbd traps

## Pitfalls

- Provider access and retention are external operational dependencies.
- Setup secures the WebUI login and finishes OK without a Usenet provider, noting what is left. Add your own authorized provider in Config > Servers; Setup does not create or test provider accounts.
- A first-run wizard is not API failure: readiness uses the version API, then verifies authenticated queue/history. Explicit empty arrays and zero download rate are valid.
- Setup saves the existing full API key as `SABNZBD_API_KEY` through the Project secret boundary. The NZB upload-only key cannot read queue/history. Retry Setup to recover a missing saved key without rotation.
- The source-verified Homarr 2.4.1/SABnzbd 5.1.3 contract and pending runtime acceptance are recorded in [the SABnzbd Link contract](../../homarr-sabnzbd-contract.md).
- Shared layouts mount `${DATA_ROOT}/usenet` at `/data/usenet`; Setup sets Temporary and Completed Download Folders to `/data/usenet/incomplete` and `/data/usenet/complete`. Legacy App-local `/data` and any existing `/downloads` mount keep their paths; Setup does not migrate files or pending jobs.
- Sonarr, Radarr and Lidarr declare an additional SABnzbd Link without replacing qBittorrent. They discover their native `Sabnzbd` schema, reuse the existing full API key and test the recorded connection after target/category/path checks. See [the Arr Link contract](../../arr-sabnzbd-contract.md).
- Native SABnzbd protocol is consumer-specific: Sonarr/Radarr API v3 use `usenet`; supported Lidarr 3.x API v1 source families expose either `usenet` or `UsenetDownloadProtocol`. The shared admission seam preserves the unique authenticated schema's exact literal and requires the recorded resource to match it before target reads or native tests. Known literals are not interchangeable aliases: crossed schema/resource values stay Manual, without protocol normalization or ownership migration. Supported pairs remain Sonarr v3/`tvCategory`, Radarr v3/`movieCategory` and Lidarr v1/`musicCategory`.
- The older pinned Lidarr family ([3.1.0.4875 source](https://github.com/Lidarr/Lidarr/blob/350860e524029b7fb4165ed14fbcabb11217ada2/src/NzbDrone.Core/Download/UsenetClientBase.cs#L36)) returns the Usenet enum, [serialized camel-case](https://github.com/Lidarr/Lidarr/blob/350860e524029b7fb4165ed14fbcabb11217ada2/src/NzbDrone.Common/Serializer/System.Text.Json/STJson.cs#L33). The newer pinned family ([3.1.6.5079 source](https://github.com/Lidarr/Lidarr/blob/77de65260250020be99e417b027752b1f1730c08/src/NzbDrone.Core/Download/UsenetClientBase.cs#L36)) returns `nameof(UsenetDownloadProtocol)`; [the factory copies it](https://github.com/Lidarr/Lidarr/blob/77de65260250020be99e417b027752b1f1730c08/src/NzbDrone.Core/Download/DownloadClientFactory.cs#L38-L43), and [the v1 mapper preserves it](https://github.com/Lidarr/Lidarr/blob/77de65260250020be99e417b027752b1f1730c08/src/Lidarr.Api.V1/DownloadClient/DownloadClientResource.cs#L8-L26). These snapshots establish contracts, not a version cutoff. Replacing one literal with the other universally was a leaf/fixture defect, not a folder/category prerequisite; native/runtime acceptance remains separate.
- In Config > Categories, relative folders live beneath the completed folder; absolute folders override it. Match the consuming App's category and save each row. Existing category folders and Arr category choices are preserved. SABnzbd's default suggestions include `tv`, `movies` and `audio`, not `music`: a missing chosen category remains a specific Manual step. No Link creates categories, changes sorting/scripts, starts a job or contacts a provider.
- A category must keep job folders enabled (no trailing `*`) and have no effective moving script or active sorting. Review those choices explicitly rather than expecting Setup to rewrite them. An unset Lidarr music root/profiles, inaccessible folder or incompatible App-local legacy storage stays Manual with persisted recovery. Use the actual shared directory or an existing reviewed Remote Path Mapping; Setup does not migrate media, libraries or mounts.
- Before queue/category-list reads or Arr native tests, the Link verifies existing absolute incomplete/completed folders as the App user and probes the existing `*` category directly. Missing prerequisites or relative global folders stay Manual; status reads can create directories and category-list reads can initialize/save defaults, so they are not used to repair or resolve prerequisites. Relative category folders under a verified absolute completed folder remain supported.
- The default uses shared Host PUID/PGID/UMASK; optional separate media users use an App-specific PUID, shared PGID and media umask `002`. An explicit Permissions for completed downloads setting can override the process umask; Setup does not change it. Shared storage needs compatible mounts/filesystems and permissions; separate download/library mounts cannot provide cross-mount hardlinks or atomic moves. See [Media Setup](../media-setup.md).
- Sources: [SABnzbd folders](https://sabnzbd.org/wiki/configuration/5.1/folders), [relative category folders](https://sabnzbd.org/wiki/configuration/5.1/categories), and [LinuxServer mounts and UMASK](https://docs.linuxserver.io/images/docker-sabnzbd/).

## Security

- Treat provider credentials, server configuration, and the SABnzbd API key as secrets.
- Keep its WebUI private; the API key is accepted as a query parameter by the upstream API.
- Homarr SABnzbd credential-safety hold #363: the pinned native adapter sends the full API key in the request query. A rejected response can retain that Address into downstream logs. Homarr Link Check/apply must remain Manual before any request or mutation until a supported adapter and complete logging-chain fix are verified in the actual supported image. Do not manually activate the integration or bypass the hold; standalone SABnzbd Setup and owned Link removal stay separate.
